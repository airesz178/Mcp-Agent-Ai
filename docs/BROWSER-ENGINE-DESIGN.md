## Step 3 official Sign in with ChatGPT OAuth (2026-11-05, current)

**Root cause corrected:** Previous revisions opened the normal ChatGPT website in a Chrome Custom Tab, which correctly reused the user's signed-in Chrome cookies but could never report that website session as an authenticated *app-owned WebView*. It lacked an app-specific authorization callback, so the backend kept **Bring Session** disabled even though Chrome was logged in.

**Current Android implementation:** New native `android/ChatGptOAuthPlugin.kt` and Tauri `src-tauri/src/android_chatgpt_oauth.rs` invoke the official [open-source Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) flow. Step 3 retains exactly two buttons: **Sign in to ChatGPT** initiates OAuth registration/authorization through `https://auth.openai.com/api/accounts/authorize` in Chrome; **Bring Session** requires an authenticated OAuth ID token **and** explicit `chatgpt.tokens.use.direct` and `resource.invoke` plan scopes, then performs a read-only bearer-authenticated `GET https://api.openai.com/v1/models` check before recording the connection. The UI polls the native result, turns both buttons gray after a true linked result, and advances to Step 4. Revocation, expiration and failed verification do not count as success. A cancelled Chrome flow can be retried immediately.

The first request uses `dynamic_agent_client`, persistent per-device `urn:uuid:` host ID, name hint, random state/nonce and S256 PKCE challenge. A single 127.0.0.1 loopback listener is bound **before** opening Chrome and checks exact GET path/Host/state, then exchanges the code using the **issued** `oaiapp_...` client ID. The Android plugin verifies an RS256-signed ID token against OpenAI JWKS, issuer, audience, expiry, nonce and identity before accepting it; token-response scopes determine plan permission. Credentials are protected by AndroidKeyStore AES-GCM, remain native and are refreshed with rotating refresh tokens. The redirect response carries **no credentials** and can return to the app by a `mcpagentai://auth-complete` link. No Chrome cookies, tokens, email, user identifiers or ChatGPT conversations are exported to web UI or the private ChatGPT WebView. The previously built private WebView remains separate for its own other features.

## One application-facing browser contract

- `get_browser_capabilities` returns actual capabilities per engine and runtime (`canOpenExternal`, `canRunHidden`, `canInstallExtensions`, supported package formats, supported tabs/DOM/actions). Values come from runtime probes, not static optimistic labels.
- `select_browser` is an **explicit user-initiated** setting. Switching stops the unselected app-owned engine, invalidates prior pending tab/extension requests, and never imports cookies or live sessions automatically.
- `open_owned_tab`, `list_owned_tabs`, `close_owned_tab`, `stop_owned_browser` operate only on app-owned tabs, using bounded receipts and scoped IDs. External-browser control is a separate, explicitly paired route.
- `list_extensions`, `review_extension_permissions`, `install_compatible_extension`, `enable_extension`, `disable_extension`, and `remove_extension` are exposed **only when runtime-capable**. Enforce manifest/source/signature checks, user approval, declared host permissions, safe defaults and reliable revocation. Never execute an unreviewed downloaded extension.
- Browser actions must preserve existing user data, not grant accessibility/screen/file permissions, and fail closed when ownership or current consent cannot be proven.
- Background means app-owned browser work without a visible tab/window *while the app and OS allow it*. On Android it does **not** imply unrestricted 24/7 process lifetime; do not silently install a foreground service or ignore Android battery restrictions.
